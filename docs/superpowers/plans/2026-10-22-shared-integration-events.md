# Shared integration events

Реализация на main по согласованным правилам `docs/ai/rules/integration-events.md`.
Публичные DTO не зависят от Shared, инфраструктуры и Symfony.

## Решения

- Инфраструктурный кодек с атрибутом AsIntegrationEvent связывает публичный
  PHP-тип с source/type/schemaVersion и явно кодирует JSON-схему payload.
- Подписчик в Infrastructure/Integration регистрируется атрибутом
  AsIntegrationEventSubscriber с постоянным id. Его __invoke принимает
  публичный DTO и IntegrationEventMetadata.
- IntegrationEventPublisher требует активную default-транзакцию. Он создаёт
  eventId один раз, фиксирует время операции в UTC и JSON-снимок, затем пишет
  отдельную IntegrationEventEnvelope для каждого подписчика через OutboxBus.
- Состав подписчиков определяется при публикации. Новые подписчики не получают
  историю. Публикация без подписчиков допустима, записей очереди не создаёт.
- В очереди нет PHP-типов бизнесовых DTO: только общие технические типы,
  JSON-payload, метаданные и id получателя. Worker декодирует снимок по логическому
  ключу схемы и вызывает ровно одного получателя в транзакции outbox.bus.
- Повтор доставки сохраняет eventId и повторяет только этого получателя.
  Бизнесовая идемпотентность остаётся обязанностью потребителя; новых таблиц
  дедупликации, зависимостей и миграций не добавляется.
- Неизвестные схемы/получатели и некорректный payload не ретраятся как временные
  ошибки. Исключения самого подписчика обрабатываются обычной retry-политикой.
- Предпочтение атрибутам касается всех поддерживающих их механизмов. services.yaml
  подключает узкие ресурсы; лишние Class: ~, aliases и wiring не добавляются.
  Адаптеры шин используют AsAlias, HTTP listener — AsEventListener, расписание —
  AutowireIterator. Именованные шины Messenger и default Connection autowire
  разрешает без дополнительных arguments. DTO не регистрируются сервисами.

## Окружение

Исходная ветка demo-gemini сохранена. Worktree main — отдельный временный каталог.
Пользователь разрешил изолированные PHP/PostgreSQL контейнеры и отдельную *_test БД.
Существующий PHP-образ: PHP 8.5.10, необходимые PDO-расширения присутствуют.
Для Symfony-тестов используется memory_limit=512M; стартовый лимит 128M
недостаточен для сборки test-контейнера.

## Результаты проверок

- `make test`: 91 тест, 263 проверки, без пропусков, включая PostgreSQL.
- `make lint`: PHPStan и PHP-CS-Fixer без ошибок.
- `make architecture`: нарушений, предупреждений и непокрытых зависимостей нет.
- `lint:container --env=test` и `--env=prod`: успешная сборка и проверка типов.
- `doctrine:schema:validate --skip-sync --env=test`: маппинг корректен.
- PHP 8.4.27: `make test-unit` — 73 теста, 166 проверок; `make cs-check` без замечаний.
- После общего уточнения DI повторно прошли test/lint/architecture, контейнеры
  test/prod, Doctrine metadata и unit/cs-check на PHP 8.4.27. Отдельная проверка
  YAML-загрузчика подтвердила пять private aliases из AsAlias, исключение DTO
  из ресурсов и отсутствие автоматического alias при discovery одной реализации
  без интерфейса. ExceptionListener зарегистрирован один раз.
- Независимое ревью: критичных и важных замечаний нет. Рекомендованы
  дополнительные отрицательные DI-сценарии и отдельный сценарий полного
  цикла worker retry/failed/recovery. Текущие тесты проверяют повтор через
  шину, сохранение снимка и независимость обработчиков.

Зависимости и миграции не изменялись. Для тестов применена существующая
миграция только к согласованной изолированной test-БД.
