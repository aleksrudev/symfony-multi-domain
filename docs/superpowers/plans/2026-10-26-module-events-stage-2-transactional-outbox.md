# Этап 2. Переиспользуемый Transactional Outbox

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Сохранять сериализуемый объект атомарно с бизнесовыми данными и доставлять его через подставляемый инфраструктурный адаптер.

**Architecture:** Outbox принимает object, сохраняет самостоятельный снимок и передаёт восстановленный объект в OutboxPublisherInterface. Механизм не знает IntegrationEvent, Symfony Messenger, Envelope и имени целевой шины. Текущая композиция с Messenger появится на этапе 4.

**Tech Stack:** PHP >= 8.4.17, PostgreSQL 16, DBAL 4, Doctrine Migrations, PSR Clock, Symfony Console для технических команд, PHPUnit.

**Spec:** [Раздел 5](../specs/2026-10-24-module-events-design.md); [общие ограничения](2026-10-26-module-events-implementation.md).

## Global Constraints

Этап 1 задаёт архитектурные правила. Этап не зависит от Idempotent Consumer и
контракта интеграционного события. Создание/применение миграции требует
согласования по AGENTS.md. До этапа 4 компоненты подключены только в отдельном
test-kernel. Новый прикладной канал и универсальная Application-шина не вводятся.

## Review Focus

- Обычный DTO без IntegrationEventInterface сохраняется и доставляется — задача 2.
- Снимок и бизнесовые данные коммитятся/откатываются вместе — задача 2.
- Relay зависит от нейтрального порта доставки, имя event.bus ему неизвестно — задача 3.
- Ошибка/конкуренция не теряет исходящую запись; повторная отправка допустима — задача 3.
- Неуспешная запись восстанавливается с прежним снимком без знания метаданных события — задача 4.

**Interfaces:**

- Consumes: один default DBAL connection; таблица Messenger не нужна.
- Produces: только `shared.outbox_messages`. Схема processed_messages принадлежит этапу 3.

| Поле | Тип и ограничение |
| --- | --- |
| `id` | `BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY` |
| `body` | `TEXT NOT NULL` — base64 от штатного PHP serialize объекта |
| `created_at`, `available_at` | `TIMESTAMP(6) WITHOUT TIME ZONE NOT NULL`, UTC |
| `attempts` | `INT NOT NULL DEFAULT 0 CHECK (attempts >= 0)` |
| `failed_at` | nullable `TIMESTAMP(6) WITHOUT TIME ZONE` |
| `last_error` | nullable `TEXT` |

Индекс готовых записей: `(available_at, id) WHERE failed_at IS NULL`.
Колонки source, event_id, transport, bus и Messenger headers отсутствуют.
Адрес текущего способа доставки задаётся DI-композицией, а не самим сообщением.
Foreign key на бизнесовые таблицы и ORM-сущность Outbox не создаются.

## Готовность этапа

Outbox сохраняет и доставляет произвольные поддерживаемые PHP-объекты без
IntegrationEvent и Messenger в его API/механизме. Таблица Idempotent Consumer
и event.bus для этих проверок не нужны. Композиция с интеграционными событиями —
[этап 4](2026-10-26-module-events-stage-4-messenger-cutover.md).

после исправления проходят: проверяется также native __serialize-состояние;
пользовательские сериализационные hooks повторно не вызываются.
Общая событийная доставка, production discovery и worker не переключены.
