# Доменные типы

Применяй при создании, изменении и ревью доменных моделей, интерфейсов
репозиториев, DataProvider и маппинга доменных типов. Границы слоёв и модулей описаны
в [архитектуре](architecture.md); конкретные типы и ограничения —
в AGENTS.md модуля владельца.

## Идентификаторы

Идентификаторы сущностей и агрегатов по умолчанию моделируй отдельными
неизменяемыми value objects: `ProductId`, `OrderId`. Используй эти типы
в свойствах, конструкторах, аргументах и результатах методов доменных объектов,
а также в интерфейсах доменных DataProvider. Например, `Product::$id` имеет
тип `ProductId`, а `ProductDataProviderInterface::findById()` принимает `ProductId`.
Разделение записи и поиска описано в [правилах доступа к данным](data-access.md).

ID value object делай `final readonly`, с равенством по значению, явным
преобразованием в скаляр и проверкой согласованных ограничений идентификатора.
Не вводи UUID, генерацию или новый формат без требования задачи. Использование
скалярного ID в доменной модели требует обоснования в AGENTS.md владельца.

## Закрытые наборы значений

Закрытый набор допустимых доменных значений моделируй PHP enum: например,
валюты или статусы. Для стабильного строкового или числового представления
используй backed enum. Поле, аргументы и результаты доменных методов должны
использовать сам enum, а не его скалярное значение.

Состав cases определяют требования. Если разрешена только RUB, `Currency`
содержит только `case RUB = 'RUB'`; дополнительные валюты не добавляй
«на будущее». Изменяемый справочник не заменяй enum. Обычный булев признак
не требует enum без самостоятельного доменного смысла состояний.

## Владение и границы

Размещай бизнесовые ID в `src/<Module>/Domain/ValueObject/`, enum —
в `src/<Module>/Domain/Enum/`. Не выноси их в Shared и не импортируй
Domain-типы другого модуля.

Преобразование входных скаляров в доменные типы выполняй до передачи
в доменную модель или DataProvider. Для HTTP, сообщений и публичных Contracts
явно преобразовывай доменные типы в представление соответствующего контракта.
Presentation/Contracts не должен импортировать внутренние Domain-типы; потребитель
переводит полученные значения в собственные типы через интеграционный адаптер.

Не заменяй доменный тип примитивом ради удобства Doctrine. Маппинг и
преобразование при сохранении и загрузке обеспечиваются инфраструктурой.
Не оборачивай каждое скалярное поле в value object автоматически: для остальных
значений учитывай их доменный смысл, инварианты и поведение.

## Проверка при изменении типов

- Проверь использование ID value objects и enum во всём затронутом доменном API,
  включая интерфейсы DataProvider.
- Проверь равенство ID по значению и отказ при нарушении заданных ограничений.
- Проверь обработку недопустимого входного значения enum на границе.
- При изменении маппинга проверь сохранение и загрузку типов через Doctrine,
  включая поиск сущности по ID.
- Проверь скалярное представление в публичном API и отсутствие зависимости
  Presentation/Contracts от Domain.
