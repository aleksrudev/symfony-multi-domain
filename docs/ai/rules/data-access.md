# Репозитории, DataProvider и коллекции сущностей

Применяй при создании, изменении и ревью интерфейсов доступа к сущностям,
их реализаций и коллекций. Границы слоёв описаны в [архитектуре](architecture.md),
типы идентификаторов — в [правилах доменных типов](domain-types.md).

## Запись

Доменный `{Entity}RepositoryInterface` размещай в `Domain/Repository/`.
Он объявляет только два метода: `save(Entity $entity): void` и
`remove(Entity $entity): void`. Не добавляй методы поиска, подсчёта, проверки
существования, массового изменения или управления транзакциями, в том числе
через наследование интерфейсов.

Реализация находится в `Infrastructure/Persistence/Doctrine/`. Репозиторий
не вызывает `flush()` самостоятельно; транзакцией управляет сценарий
использования через принятую в проекте инфраструктуру команд.

## Чтение

Для поиска создавай доменный `{Entity}DataProviderInterface` в
`Domain/DataProvider/`. Реализация находится в `Infrastructure/Persistence/Doctrine/`
и выполняет запросы к БД через Doctrine. DataProvider не сохраняет и не удаляет
сущности, не изменяет их бизнес-состояние.

Методы возвращают только сущность владельца, `{Entity}Collection` либо
`{Entity}PaginatedCollection`. Не возвращай `null`, массивы, отдельные скаляры,
прикладные DTO, Doctrine Query или Paginator. Подсчёт внутри реализации допустим
для формирования пагинированной коллекции.

Поиск одной сущности возвращает её либо выбрасывает доменное
`{Entity}NotFoundException`, наследующее Shared Domain `DomainException`.
Отсутствие совпадения по фильтру имеет ту же семантику: скрытый товар для
`findPublishedById()` считается ненайденным. Поиск множества при отсутствии
совпадений возвращает пустую типизированную коллекцию.

Идентификаторы в аргументах имеют соответствующий тип value object. Например:

```php
interface ProductDataProviderInterface
{
    /** @throws ProductNotFoundException */
    public function findById(ProductId $id): Product;

    /** @throws ProductNotFoundException */
    public function findPublishedById(ProductId $id): Product;

    public function findPublishedPaginated(int $offset, int $limit): ProductPaginatedCollection;
}
```

Application и доменные Action используют DataProvider для загрузки сущностей
и Repository для их сохранения или удаления. Разделение ответственности
описано в [правилах доменных Action](domain-actions.md).
Presentation не обращается к ним напрямую.
Если публичный контракт предусматривает отсутствие результата как `null`,
его реализация преобразует конкретное `{Entity}NotFoundException` в `null`.
Не меняй такой контракт автоматически и не перехватывай все доменные ошибки
как отсутствие сущности.

## Коллекции и пагинация

Для каждого типа сущности создавай отдельный класс `{Entity}Collection`
в `Domain/Collection/`, наследующий
`App\Shared\Domain\Collection\AbstractCollection<Entity>`. Укажи generic-тип
в `@extends` и конкретный класс элемента в `elementClass()`:

```php
/** @extends AbstractCollection<Product> */
final class ProductCollection extends AbstractCollection
{
    protected function elementClass(): string
    {
        return Product::class;
    }
}
```

Основа наследует Doctrine `ArrayCollection`, предоставляет итерацию, подсчёт
и проверку типа элементов при создании, `add()`, `set()` и записи через `[]`.
Не дублируй конструктор и эти проверки в конкретных коллекциях.
Прямое наследование бизнес-коллекций от Doctrine запрещено.
Не импортируй Doctrine Collections в другие доменные классы.

`filter()`, `partition()` и `map()` создают коллекции того же конкретного класса
и проверяют тип результата. Поэтому `map()` может возвращать только тот же тип
сущности; преобразование в DTO выполняй вне коллекции, например через `all()`.
`toArray()` сохраняет ключи, `all()` возвращает `list<Entity>` с новыми индексами.

Пагинация возвращает доменную модель `{Entity}PaginatedCollection` из того же
каталога. Это отдельная readonly-модель, не наследник `AbstractCollection`.
Она содержит `{Entity}Collection $items` и `int $count`:

```php
final readonly class ProductPaginatedCollection
{
    public function __construct(
        public ProductCollection $items,
        public int $count,
    ) {
    }
}
```

`count` — общее количество сущностей, соответствующих фильтру, до применения
offset/limit. Количество элементов страницы — `count($result->items)`.
Запрос страницы и запрос общего количества используют одинаковый фильтр.
Страница имеет стабильную сортировку, при равенстве основного поля — по ID.
Пустая страница допустима, в том числе при положительном общем `count`.
DataProvider возвращает эту доменную модель. Query-обработчик преобразует
сущности её элементов в модели результата Application по
[правилам результатов Query](domain-actions.md#результаты-query).
Доменная коллекция не должна попадать в результат Query даже как вложенное поле.
Отдельный порт проекций для этой пагинации не нужен.

## Проверка изменений

- Репозиторный интерфейс имеет только `save()` и `remove()` с конкретной сущностью.
- Поиск находится в DataProvider; его результаты соответствуют разрешённым типам.
- Поиск одной сущности выбрасывает конкретное исключение при отсутствии совпадения,
  включая отсутствие по фильтру.
- Коллекция содержит только сущности своего типа; пустая выборка возвращает
  пустую коллекцию.
- Пагинация возвращает правильную страницу и общий `count` по тому же фильтру;
  проверь также пустую страницу за пределами непустой выборки.
- Реализация проверена интеграционными тестами запросов и преобразования результатов;
  публичные контракты сохраняют согласованное представление отсутствия результата.
